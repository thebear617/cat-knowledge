### 3.3 特殊记录处理

- 两条 `¥0.00` 的捐赠记录是实物捐赠，不作为现金收入或现金支出；在标准化模型中记录为 `recordType: in_kind`，页面类型显示为“实物”。
- 一条 2025-06-09 的空金额、空类别、空事项记录视为占位/初始化记录；先保留原始事实，在标准化数据中标记为 `reviewStatus: placeholder`，默认不计入现金汇总。
- `余额` 字段存在 72 个值，但与按日期累计计算的结果有 37 个不一致，不能直接作为账户余额或页面主汇总；暂不在 UI 中展示为“当前余额”。
- `结余` 与逐行 `收入 - 支出` 在当前 328 条记录中一致；它可作为记录方向和记录净额的校验输入，但最终以标准化字段为准。
- 原始行顺序不是时间顺序，页面必须按日期排序；同日记录需要保留稳定的原始顺序作为次级排序依据。
- 疑似重复的捐款记录不自动删除。重复金额可能是真实的多笔捐款，Stage 1 只标记候选，不改变公开记录。

- 当前 `相关猫猫` 共发现 46 个不同字符串；其中 `渣男` 可映射到现有猫咪 `赫兹`。

## 4. 视觉与响应式结构冻结

### 4.1 桌面端

- 沿用 Cats 站点现有暖色视觉：米白背景、深棕文字、棕橙强调色、细边框和圆角卡片。
- 顶部为“财务公示”标题、说明文案和数据截至日期。
- 标题下方为模块内两个视图切换：`账目公示`、`价格参考`。
- `账目公示`视图先放三张汇总卡，再放主内容区。
- 主内容区为左侧账目列表、右侧账目详情的双栏结构；列表是主阅读区，详情随选中记录更新。
- 账目列表保留搜索、收支/实物筛选、类别筛选、月份筛选和排序能力。
- 账目详情保留日期、类型、类别、金额、事项、关联猫咪、公开备注和凭证可用性。
- 账目列表按月份分组；表格列和参考图一致，但实际内容只来自标准化财务数据。

### 4.2 移动端

- 采用单栏布局，账目详情从右侧栏降为选中记录后的详情区或抽屉，不强行压缩桌面双栏。
- 顶部视图切换和汇总卡保持可用；汇总卡允许纵向排列或横向滚动。
- 筛选区允许横向滚动，搜索框优先保留；列表行改为信息卡/紧凑条目，避免横向滚动宽表。
- 详情内容按“金额与类型 → 事项与关联猫咪 → 备注 → 凭证”顺序排列。
- 移动端仍保持桌面端的颜色、层级、选中态和数据口径，不另设一套业务逻辑。
