# 猫咪详情悬浮框重构规范

> 版本：v1.0
>
> 状态：设计与实现计划
>
> 参考：宽屏双栏详情页视觉稿（大面包）

## 1. 目标

将当前猫咪详情悬浮框从“窄面板 + 连续纵向信息”的展示方式，重构为宽屏、双栏、卡片化的猫咪档案面板。

这次重构的重点不是增加更多文字，而是建立清晰的信息层级，让用户打开一只猫的档案后，可以同时看到：

- 猫咪身份与状态
- 主照片与照片组
- 基础运营字段
- 性格关键词
- 故事档案
- 已确认关系
- 猫咪动态

第一版只展示动态的日期、标题和文字；动态图片继续保存在数据中，但不在详情页渲染。

## 2. 已确认的产品决策

以下内容视为本次实现的固定约束：

1. 使用宽屏悬浮窗，采用参考稿的宽高比例和双栏布局。
2. 桌面端不使用单列纵向堆叠。
3. 动态按日期从新到旧排序。
4. 动态默认显示最近 3 条。
5. 动态超过 3 条时显示“展开全部动态”，展开后可收起。
6. 动态第一版只显示日期、标题和文字，不显示动态图片。
7. `relationships` 是正式关系；`relationshipHints` 只作为“故事提及”信息，不进入正式关系视觉。
8. 正式名称使用 `name`；别名使用 `aliases`，不改变正式名称。
9. `待补充` 保持原值，不能映射为“零针”“未绝育”或其他确定状态。
10. `sourceId`、`sourceImages` 等追溯字段保留在数据中，但第一版不直接展示。

## 3. 视觉方向

### 3.1 整体气质

- 温暖、克制、像一张被认真整理的猫咪档案卡。
- 视觉重点落在猫咪照片和信息卡片上。
- 使用卡片分区承载内容，不使用 Markdown 标题加长段落的阅读感。
- 保留猫猫手册现有的暖米色、深棕色和橙色强调色。
- 装饰线只作为卡片分隔和时间线结构使用，不大面积铺设装饰线。

### 3.2 颜色 Token

```css
--cat-drawer-bg: #fbf9f5;
--cat-card-bg: #ffffff;
--cat-card-soft: #faf5ed;
--cat-text: #2f2924;
--cat-muted: #8b8177;
--cat-accent: #c98232;
--cat-accent-soft: #f8e7d0;
--cat-success: #4f8d5c;
--cat-success-soft: #e4f0e1;
--cat-line: #eee5da;
--cat-overlay: rgba(47, 41, 36, .56);
```

颜色只用于表达层级和状态：

- 橙色：标题图标、时间线节点、展开按钮、性格关键词。
- 绿色：已毕业、已绝育等确定的积极状态。
- 灰色：辅助信息、故事提及、日期和说明文字。
- 暖米色：卡片背景和关键词背景。

## 4. 页面布局

### 4.1 遮罩层

详情打开后，在主页面上覆盖半透明暖灰遮罩：

- `position: fixed`
- 覆盖整个视口
- `background: var(--cat-overlay)`
- `z-index` 低于详情窗，高于主页面
- 点击遮罩关闭详情
- 打开详情时锁定主页面滚动

背景页面可以保留轮廓和照片，但应明显弱化，避免与详情内容竞争。

### 4.2 悬浮窗

桌面端目标尺寸：

```css
width: min(86vw, 1120px);
max-height: min(90vh, 900px);
border-radius: 24px;
padding: 28px;
```

目标视觉宽高比约为 `1.35 : 1`。不使用固定高度强行裁切内容；当故事或动态较长时，悬浮窗整体可滚动。

悬浮窗结构：

```text
详情悬浮窗
├── 顶部身份栏（跨越两栏）
└── 主体双栏
    ├── 左栏：照片与基础信息
    └── 右栏：故事、关系与动态
```

### 4.3 顶部身份栏

顶部身份栏横跨整个主体区域，包含：

- 猫咪正式名称：大字号、深棕色。
- 性别图标：根据 `gender` 显示公猫、母猫或未知状态。
- 状态标签：使用 `status`，例如“就读中”“已毕业”“喵星或失踪”。
- 可选别名提示：当 `aliases` 非空时显示“别名：xxx”。
- 关闭按钮：右上角圆形按钮，支持鼠标、触摸、键盘操作。

右上角可以保留一句轻量的祝福文案作为视觉装饰，但不能取代数据字段，也不能影响关闭按钮的识别度。

### 4.4 主体网格

桌面端采用双栏网格：

```css
grid-template-columns: minmax(360px, .92fr) minmax(480px, 1.08fr);
gap: 20px;
```

左栏略窄，右栏略宽。右栏承担故事和动态文本，因此需要更多横向空间。

## 5. 左栏组成

### 5.1 主照片

- 使用 `cover`，没有 `cover` 时使用 `images[0]`。
- 使用本地图片路径，不直接使用 `sourceImages`。
- 图片采用较大的圆角矩形，不使用小圆头像作为主视觉。
- 建议比例 `4 : 3`，使用 `object-fit: cover`。
- 点击主图可以打开现有的大图查看器。

### 5.2 照片缩略图组

- 主图下方横向排列最多 4 张缩略图。
- 使用已经生成的 `thumb/` 图片。
- 点击缩略图切换主图，或沿用现有的大图查看行为。
- 没有照片时显示统一的“暂无照片”占位，不显示破图。

### 5.3 基础信息卡

使用 2 × 2 网格展示高频字段：

| UI 标签 | 数据字段 | 展示规则 |
| --- | --- | --- |
| 区域 | `area` | 直接显示值；未知时显示“待补充” |
| 性别 | `gender` | 公 / 母；空值显示“待补充” |
| 绝育 | `sterilized` | 已绝育 / 未绝育 / 待补充 |
| 疫苗 | `vaccine` | 由页面摘要显示；具体记录作为辅助文字 |

“待补充”是有效信息，使用低强调但可读的文字显示，不隐藏、不转义为其他状态。

### 5.4 性格关键词

当 `personality` 非空时显示关键词卡片：

- 标题：性格关键词。
- 每个关键词一个浅橙色胶囊标签。
- 标签不承载点击行为。
- 不把关键词重新拼成一段逗号分隔的长文本。

## 6. 右栏组成

### 6.1 故事档案卡

字段：`description`。

展示规则：

- 有故事时显示“故事档案”卡片。
- 使用正常段落排版，行高约 `1.7`。
- 保留原始换行，但不额外生成 Markdown 标记。
- 故事较长时由悬浮窗整体滚动承载，不在第一版引入额外的故事折叠按钮。
- 没有故事时不渲染空卡片。

### 6.2 关系卡

字段：`relationships`、`relationshipHints`。

正式关系：

- 只使用 `relationships`。
- 显示关系对象名称和关系类型，例如“黑哥 · 夫妻”。
- 用正常的卡片或胶囊元素表示。
- 标题区域可显示“已确认关系”。

故事提及：

- `relationshipHints` 单独放在“故事提及”区域。
- 使用虚线边框、灰色文字或低饱和样式弱化。
- 不显示为已确认关系，不用于正式关系图或关系统计。
- 关系类型不确定时显示候选描述或“关系待补充”。

没有正式关系和故事提及时，不渲染关系卡。

### 6.3 猫咪动态卡

字段：`updates`。

动态处理规则：

1. 复制数组后按 `date` 从新到旧排序，不直接修改原始数据。
2. 默认取排序后的前 3 条。
3. 每条动态显示：日期、可选标题、文字内容。
4. 动态没有标题时不显示空标题。
5. 动态没有文字时显示“暂无文字记录”。
6. 第一版不渲染 `updates[].images`。
7. 动态数量大于 3 条时，显示“展开全部动态（共 N 条）”。
8. 展开后显示全部动态，按钮文字变为“收起动态”。
9. 动态时间线只使用少量结构线和节点，不做复杂图表。

建议结构：

```text
猫咪动态                         [共 N 条]
│  2026-06-09   动态标题
│               动态文字……
│  2026-04-25   动态标题
│               动态文字……
│  2026-03-31   动态标题
│               动态文字……
└  [展开全部动态（共 N 条）]
```

## 7. 字段与展示边界

### 7.1 第一版展示字段

```text
name
status
gender
area
sterilized
vaccine
personality
description
relationships
relationshipHints
updates
aliases
images
```

### 7.2 第一版保留但不展示字段

```text
sourceId
sourceImages
updates[].images
```

这些字段用于后续追溯、图片归档或二期功能，不应在第一版详情中出现原始 URL。

### 7.3 空值与待补充

| 数据情况 | UI 处理 |
| --- | --- |
| `待补充` | 显示为“待补充”，使用低强调样式 |
| `null` / 空字符串 | 对应卡片不显示，或在必须展示的基础信息中显示“待补充” |
| 空数组 | 不渲染对应模块 |
| 动态无文字 | 显示“暂无文字记录” |
| 关系候选不确定 | 放入“故事提及”，不当作正式关系 |

## 8. 响应式规范

### 8.1 桌面端（`min-width: 720px`）

- 使用双栏布局。
- 悬浮窗居中显示。
- 悬浮窗最大宽度约 1120px。
- 主照片、缩略图和基础信息保持左栏完整性。
- 右栏的故事、关系、动态按卡片连续排列。

### 8.2 移动端（`max-width: 719px`）

移动端允许退化为单列，但仍保留卡片化结构和信息层级：

1. 顶部身份栏
2. 主照片与缩略图
3. 基础信息卡
4. 性格关键词
5. 故事档案
6. 关系
7. 动态

移动端要求：

- 悬浮窗宽度接近视口宽度，保留安全边距。
- 内容由悬浮窗整体滚动。
- 动态展开后不能被固定高度裁切。
- 长名称、长故事和长关系名称允许换行。
- 关闭按钮始终可见且容易点击。

## 9. 交互与可访问性

- 点击猫咪卡片打开详情。
- 点击关闭按钮、遮罩或按 `Escape` 关闭详情。
- 打开详情时锁定背景页面滚动，关闭后恢复原滚动位置。
- 展开/收起动态按钮使用真实 `<button>`。
- 按钮有 `aria-expanded` 状态。
- 关闭按钮有明确的 `aria-label`。
- 动态日期使用 `<time datetime="YYYY-MM-DD">`。
- 图片有以猫咪名称为基础的 `alt` 文本。
- 颜色不能成为识别状态的唯一依据，文字必须同时出现。

## 10. 分步实现计划

### 阶段 0：保留现状并准备参考数据

工作内容：

- 选取“大面包”“二柑”“胆小橘”“邪恶奶牛”作为验收样本。
- 确认这些样本分别覆盖：有多条动态、关系提示、别名、待补充和无扩展数据。
- 不改变 `js/cats.js` 字段结构。

验收标准：

- 四个样本可以通过 `name` 正常找到。
- 新字段类型符合候选数据约定。

### 阶段 1：重写详情悬浮窗语义结构

工作内容：

- 将现有 `renderDrawer` 拆分为身份栏、左栏、右栏和照片区。
- 新增独立渲染函数：
  - `renderDrawerArchive`
  - `renderDrawerRelationships`
  - `renderDrawerUpdates`
- 先完成字段正确渲染，不追求最终视觉细节。

验收标准：

- 详情悬浮窗不再是连续单列文本。
- 有数据的模块显示，没有数据的模块不显示。
- 正式关系和故事提及关系分开。

### 阶段 2：实现桌面端双栏视觉

工作内容：

- 调整悬浮窗最大宽度、最大高度、圆角和内边距。
- 增加双栏 CSS Grid。
- 实现主图、缩略图、2 × 2 基础信息卡和右侧内容卡。
- 统一颜色、边框、阴影、标题和标签 Token。

验收标准：

- 桌面端详情窗接近参考稿的宽高比例。
- 左右栏具有清晰边界，视觉重心稳定。
- 长故事不会把所有信息挤成一列。
- 首页背景被遮罩弱化，详情窗成为主要视觉焦点。

### 阶段 3：实现动态默认三条与展开交互

工作内容：

- 对动态按日期倒序。
- 默认渲染 3 条。
- 增加展开全部和收起按钮。
- 切换照片分页或窗口尺寸时保留动态展开状态。

验收标准：

- 动态较多的猫默认只显示 3 条。
- 展开后能看到全部动态。
- 收起后恢复 3 条。
- 动态只出现日期、标题、文字，不出现动态图片 URL 或图片元素。

### 阶段 4：移动端与可访问性

工作内容：

- 在 719px 以下切换为单列卡片布局。
- 检查长名称、长故事、长动态和空值。
- 检查键盘关闭、Escape 关闭、遮罩关闭和滚动锁定。
- 检查按钮的 `aria-expanded`、`aria-label` 和 `<time>`。

验收标准：

- 手机宽度下没有横向溢出。
- 动态展开后仍能完整滚动。
- 所有交互控件可以通过键盘操作。

### 阶段 5：验收与清理

工作内容：

- 运行 `npm run build`。
- 浏览器检查 4 个验收样本。
- 检查所有主图和缩略图路径。
- 检查正式关系、故事提及、别名和待补充字段。
- 清理旧的详情渲染分支和不再使用的样式。

验收标准：

- 构建通过。
- 详情窗在桌面端和移动端均可打开、关闭和滚动。
- 无控制台错误、破图和重复关系。
- 第一版不请求或渲染动态图片。

## 11. 二期候选项

以下内容不进入本次粗实现：

- 动态图片本地化与图集查看。
- 故事档案的折叠/展开。
- 关系对象点击跳转到另一只猫的详情。
- 动态按年份或月份筛选。
- 来源信息和 API 原始数据查看。
- 详情页独立 URL 或分享链接。

## 12. 实现文件边界

本次重构预计涉及：

- `src/scripts/legacy-app.js`：详情悬浮窗结构、字段渲染和动态交互。
- `css/style.css`：悬浮窗尺寸、双栏网格、卡片和响应式样式。
- `js/cats.js`：本次不改字段结构；只消费已有数据。

图片继续使用：

- `public/images/{猫名}/` 原图
- `public/images/{猫名}/thumb/` 缩略图

第一版不新增动态图片下载，也不把外部图片 URL 直接暴露给详情页。
